# Naver Blog Agent

**사용자 원본을 기반으로 초안을 작성·검수하고 네이버 임시저장까지 처리합니다.** 최종 발행/예약발행은 사용자가 직접 합니다.

운영 계획 기준 2026-10-04 KST · 적용 시작 2026-10-05 KST

**매일 심화 콘텐츠 1편**: 월·화·목·토·일 육아, 수 운동, 금 투자입니다.
가족-AI 튜토리얼은 새 영상·실제 제작 자료가 있을 때만 육아(네이버 1)의 선택적 편집 하위유형으로 다룹니다. 화·토 AI 의무 편성은 없습니다.
10월 5~18일은 측정 구간이며 이후에도 사용자 결정 전까지 하루 1편을 계속하는 구현 가정입니다.
전체 운영 기준과 전환 확인은 [DAILY_PLAN](docs/DAILY_PLAN.md)을 따릅니다.

| 카테고리 | 입력 | 게시글 구조 |
|---|---|---|
| 요리 | 사용자가 올린 레시피와 사진이 모두 있을 때만 | 소개·재료 → 조리 순서 → 제공된 팁·사진 설명 |
| 육아 | 선우 관련 실제 질문 | 질문·핵심 답변 → 월령별 조건·근거 → 실천 방법·주의사항 |
| 가족-AI | 새 영상·실제 소유자 제작 자료가 있을 때만, 육아 하위유형 | 실제 환경·결과 → 재현 단계·설정 → 체크리스트·공식 직접 링크 |
| 운동 | 실제 소유자 질문 | 준비·수행 → 올바른 자세·오류 → 안전장치·중단 신호 |
| 투자 | [kis-community-bot](https://github.com/jinhoo-choi/kis-community-bot)의 심사 통과 자료 | 이슈·사실 → 해석 → 리스크 → 출처·기준일 |

실제 당일 입력이 없으면 보류합니다. 14개 주제를 미리 채우거나 다른 카테고리로 대체하지 않습니다.
금요일 투자는 기존 최신성·품질 문턱을 통과한 KIS 원본만 사용합니다. 요리는 정기 배분 밖의 별도 요청입니다.

## 자동화 흐름

실제 입력 큐 + 금요일 적격 커뮤니티 자료 → 기존 09:00 KST API 준비 → 암호화 인계 → 09:15 Work 임시저장 → 10:15 복구 점검 → 사용자 확인·발행

- 큐: `blogbot enqueue --file <입력.json>`으로 로컬 PC에 등록합니다.
- 투자: 원본 저장소의 최신 결과를 커밋에 고정해 읽으며 실행·수정·발송하지 않습니다.
- 품질: 6항목 30점 중 24점 이상, 정확성·안전성 각각 4점 이상. 재작성 최대 1회.
- 근거: 해당 주제의 1차 자료로 사실을 검수합니다. 네이버 검색 상단 5~10개 글은 구조·문체 특성만 비교하며 문장·주장·경험은 복제하지 않습니다.
- 구성: 대제목 4~6개와 소제목·짧은 문단으로 나누고, 육아·투자 이미지는 글 내용에 맞춰 자동 생성해 문단 사이에 넣습니다.
- 중복: 원본 ID당 한 번만 생성하고 KST 일일 후보 한도를 API 호출 전에 예약합니다. 준비·저장·복구 합산 1편이며 당일 재시도는 같은 ID·기존 한도를 재사용합니다.
- 심화: 매일 실제 근거·실천 단계·체크리스트/재사용 자료·공식 직접 링크를 확인합니다. 주제마다 목차와 자료를 다르게 구성하며 필수 실물 자료가 부족하면 보류합니다.
- 비용: 기존 모델·글당 이미지 수·재시도·심사 문턱을 유지합니다. 과거 날짜의 유료 원고는 보존·보류하며 자동 재과금·재저장하지 않습니다.
- 원고·사진·이력: 공개 저장소 밖의 로컬 PC에 보관합니다.
- 저장: 임시저장 완료 메시지가 있어야 성공 처리하며 미확인 저장은 자동 재시도하지 않습니다.

## 운영 연결

**구성 반영과 실제 준비·저장 결과는 별개입니다.** PR #21의 main 반영, 외부 Work 지시문 동기화, 10월 5일 자연 준비의 예약 건너뜀을 확인했습니다. 실제 모델 입력의 프롬프트까지 일치하는지 점검하며 불일치는 `CONFIG_SYNC_PENDING`으로 보류합니다. 현재 확인 범위와 남은 DB 이관·무인 저장 검증은 [STATE](docs/STATE.md)를 따릅니다.
실계정에서 육아·요리·투자 카테고리 번호와 SmartEditor 사진 첨부·임시저장 동작을 확인했습니다. 요리는 사용자 원본 사진만 사용하고, 육아·투자는 생성 이미지를 사용합니다.
ChatGPT의 새 대화·첨부 파일을 상시 읽는 연결은 없으며, 실제 질문·자료를 입력 파일로 등록해야 합니다.

1. [DAILY_PLAN](docs/DAILY_PLAN.md)의 전환 확인과 [운영 가이드](docs/OPERATIONS.md)를 확인합니다.
2. [입력 가이드](docs/INPUTS.md)에 따라 실제 당일 질문·자료와 편집 하위유형을 등록합니다.
3. 외부 Work 지시문·실행 코드·당일 receipts를 확인한 뒤 승인된 경로에서 준비·저장을 검증합니다.
4. Windows 실행기·n8n·기존 GitHub 예약은 비활성 대안입니다. 예시 기본값 1은 활성화를 의미하지 않으며 현재 경로와 동시에 켜지 않습니다.
