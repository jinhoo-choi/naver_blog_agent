# Naver Blog Agent

**사용자 원본을 기반으로 초안을 작성·검수하고 네이버 임시저장까지 처리합니다.** 최종 발행/예약발행은 사용자가 직접 합니다.

버전 0.4.0 · 대화 요구사항 기준 2026-09-26 KST

| 카테고리 | 입력 | 게시글 구조 |
|---|---|---|
| 요리 | 사용자가 올린 레시피와 사진이 모두 있을 때만 | 소개·재료 → 조리 순서 → 제공된 팁·사진 설명 |
| 육아 | 선우 관련 실제 질문 | 질문·핵심 답변 → 월령별 조건·근거 → 실천 방법·주의사항 |
| 투자 | [kis-community-bot](https://github.com/jinhoo-choi/kis-community-bot)의 심사 통과 자료 | 이슈·사실 → 해석 → 리스크 → 출처·기준일 |

입력이 없는 카테고리는 건너뜁니다. 하루 1~5건은 **생성 후보 상한**이며 분량을 채우려고 글감을 만들지 않습니다.

## 자동화 흐름

질문/레시피·사진 입력 큐 + 커뮤니티 봇 결과 → n8n 또는 GitHub 스케줄 → Windows 실행기 → 작성·검수 → 원고 보관 → 네이버 임시저장 → 사용자 확인·발행

- 큐: `blogbot enqueue --file <입력.json>`으로 로컬 PC에 등록합니다.
- 투자: 원본 저장소의 최신 결과를 커밋에 고정해 읽으며 실행·수정·발송하지 않습니다.
- 품질: 6항목 30점 중 24점 이상, 정확성·안전성 각각 4점 이상. 재작성 최대 1회.
- 근거: 육아·투자는 1차 자료로 사실을 검수합니다. 네이버 검색 상단 5~10개 글은 구조만 비교합니다.
- 구성: 대제목 4~6개와 소제목·짧은 문단으로 나누고, 육아·투자 이미지는 글 내용에 맞춰 자동 생성해 문단 사이에 넣습니다.
- 중복: 원본 ID당 한 번만 생성하고 KST 일일 후보 한도를 API 호출 전에 예약합니다.
- 원고·사진·이력: 공개 저장소 밖의 로컬 PC에 보관합니다.
- 저장: 임시저장 완료 메시지가 있어야 성공 처리하며 미확인 저장은 자동 재시도하지 않습니다.

## 운영 연결

**코드 구축과 실제 운영 연결은 별개입니다.** 사용자 PC 실행기, 필수 Secrets, 최초 네이버 로그인, 편집기 확인이 필요합니다.
실계정에서 육아·요리·투자 카테고리 번호와 SmartEditor 사진 첨부·임시저장 동작을 확인했습니다. 요리는 사용자 원본 사진만 사용하고, 육아·투자는 생성 이미지를 사용합니다.
ChatGPT의 새 대화·첨부 파일을 상시 읽는 연결은 없으며, 실제 질문·자료를 입력 파일로 등록해야 합니다.

1. [운영 가이드](docs/OPERATIONS.md)로 Secrets와 PC 실행기를 설정합니다.
2. [입력 가이드](docs/INPUTS.md)에 따라 질문 또는 레시피·사진을 등록합니다. 투자 자료는 자동 수집합니다.
3. `blogbot login`으로 네이버 최초 로그인을 완료합니다.
4. Actions → Naver Blog Draft → Run workflow에서 `count=1`, `mode=save`를 실행해 임시저장을 확인합니다.
5. n8n 또는 GitHub 스케줄 중 하나를 활성화합니다.
