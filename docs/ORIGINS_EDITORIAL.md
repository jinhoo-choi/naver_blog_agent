- 사용자가 실제로 물어본 이름·단어의 유래만 다룹니다. 날짜표·검색 트렌드·상품명으로 새 질문을 만들지 않습니다. 소유자 지정 주제와 수동 초안이 우선입니다.
- 2026-10-05 실계정 UI의 라디오 ID `9_이름의 유래`에서 실제 카테고리 번호 **9**를 확인했습니다. 화요일용 “실비김치의 실비, 이런 뜻이라고?”는 카테고리 9에서 한 번 저장한 뒤 목록 0→1로 `SAVED_NAVER`를 확인했습니다. 실제 저장은 2026-10-05 19:17 KST (10:17 UTC)이며 10월 6일 편집 예약과 다릅니다. UI 표시 `2026.10.05 03:17`은 시간대 미확인, 네이버 고유 draft ID도 미확인입니다. 서식·대표이미지 세부 검증은 확보한 증거 범위만 기록합니다. 설정이 사라지거나 미확인으로 돌아가면 `CATEGORY_CONFIGURATION_PENDING`으로 유료 호출 전에 보류합니다. 번호 추정, 기존 육아/요리 번호로 대체하거나 카테고리 확인만으로 저장 완료를 주장하지 않습니다.
- 2026-10-06은 저장 확인 후 `existing_owner_draft` 예약으로 전환했습니다. 자동 추가 생성·복구·저장을 생략하고 실제 영수증은 10월 5일로 보존합니다. 편집일 예약을 새로운 저장·발행 완료로 해석하지 않습니다.
- 모든 과거 원고와 영수증은 원래 계획·실제 저장일을 보존합니다. 새 요일 배분 때문에 과거 글을 다시 생성하거나 저장하지 않습니다.

## 짧은 본문과 상단 소개

글 상단에 아래 연재 소개를 본문 답변과 **별도 문단**으로 표시합니다. 문구를 임의로 바꾸거나 본문 첫 답변 대신 사용하지 않습니다.

> 제가 궁금했던 이름들을 정리해 두었다가, 나중에 아들에게 들려주려고 씁니다.

- 소개 다음의 **본문 첫 1~2문장**에 질문의 답을 바로 씁니다. 뜻풀이와 이름이 붙은 배경을 구별합니다.
- 본문은 대략 **350~600자**의 짧은 글을 지향합니다. 숫자는 편집 방향이며 정확한 글자 수 통과 문턱이 아닙니다. 필요한 근거와 불확실성을 빼거나 수를 채우는 반복 문장을 넣지 않습니다.
- 자연스러운 습니다체, 의미별 짧은 문단·빈 줄, 필요한 소제목만 사용합니다. 소개/본문 경계와 참고자료 앞 등 실제 전환 지점에 네이버 기본 실선 구분선을 넣습니다. `---` 기호를 그대로 노출하지 않습니다.
- 이름의 핵심 뜻·유래 단어를 절제해 **볼드**로 강조합니다. 문단 전체·모든 문장을 강조하거나 기존 심화 목차 4~6개, FAQ·체크리스트·반복 결론을 강제하지 않습니다.

## 사실과 출처

사전, 공식 기관·브랜드·지역의 자료, 신뢰할 수 있는 역사 자료에서 해당 이름의 뜻·기원·변천을 확인합니다. 실제 읽은 직접 출처를 남기고 각 주장과 맞는지 확인합니다. 서로 다른 설이 있거나 최초 사용·연대가 불확실하면 확인된 범위와 그 한계를 짧게 씁니다. 그럴듯한 민간어원·브랜드 홍보 설명을 확정된 역사로 바꾸지 않습니다.

사용자의 실제 질문과 제공 경험만 사용합니다. 구매·섭취·방문·가족 반응·아들과 나눈 대화·효능을 만들지 않습니다. 건강·안전 등 부수 주장이 생기면 해당 분야의 기존 근거·안전 기준을 유지하며 유래 확인을 효과 입증으로 확대하지 않습니다.

## 이미지와 저장 전 확인

- 입력 등록·수집에서 사용자가 제공·승인한 썸네일 **정확히 한 장**을 유료 준비 전에 확인합니다. 없으면 `INPUT_REJECTED`이며 텍스트 비용을 먼저 쓰고 이미지 준비를 기다리지 않습니다. 관리 파일명·해시·복원 후 합산 운반 예산도 재검증합니다. 새 유료 생성·이미지 5장 계획·실제 이미지 2장·캡처 3~5장·재사용 자료·공식 링크카드 수량을 유래 통과 조건으로 붙이지 않습니다.
- 썸네일은 설명용 자료이며 실제 구매·사용·방문 또는 역사 사실의 사진 증거처럼 표현하지 않습니다. 출처 검증은 별도로 합니다.
- 실제 파일·SHA-256·사용 권한, 제목/본문/이미지의 일치와 모바일 잘림, 실제 대표 설정을 확인합니다. 첫 이미지 배치만으로 대표 설정 성공이라 하지 않습니다.
- 잘못된 사실·출처, 제공되지 않은 경험, 누락된 승인 썸네일이나 미확인 카테고리는 보류합니다. 자료·날짜·번호를 창작하거나 유료 재생성으로 메우지 않습니다.
- 기존 24/30·정확성/안전성 각각 4/5, 중복 방지, 실제 저장일 영수증, 일일 한도·복구 예산을 유지합니다. 저장 완료 표시와 실제 목록을 확인하며 후기 지침의 저장 후 자동 재열기 금지 등 공통 운영 경계를 바꾸지 않습니다. 최종 발행·예약발행은 사용자 담당입니다.

## 향후 구매 경험과 쇼핑커넥트 연결

이 절은 **향후 조건부 편집 순서**입니다. 현재 글에 구매 경험·제휴 링크·내돈내산 인증을 추가하거나 쇼핑커넥트를 활성화하는 요청이 아닙니다.

1. 사용자가 실제 구매를 마친 뒤, 공개해도 되는 구체적인 경험을 제공합니다. 주문·사용 기간·맛·효과·가격·반응은 제공된 범위만 씁니다.
2. 그 제품·음식·장소와 자연스럽게 연결되는 **사용자의 실제 유래 질문**을 확인합니다. 소유자가 제공한 `purchase.origin_relevance`에 실제 구매 제품 이름과 질문의 연결을 설명하고 검수에서도 그 관계를 대조합니다. 관련 없는 상품·제휴 링크는 반려하며 판매할 상품부터 정하고 유래를 억지로 붙이지 않습니다.
3. 구매 경험과 별개로 사전·공식·신뢰할 역사 자료에서 유래를 검증합니다.
4. 사용자가 해당 글의 실제 상품과 링크 반영을 승인하고, 현재 계정에서 쇼핑커넥트 이용 가능 여부·상품 적격성과 실제 링크 대상을 확인한 경우에만 연결을 검토합니다. 링크가 없거나 부적격이면 유래 글만 유지합니다. 추측한 제휴 URL·대체 상품을 넣지 않습니다.
5. 제휴가 실제로 적용되는 글에는 구매에 따라 수수료를 받을 수 있다는 관계를 독자가 쉽게 볼 수 있게 표시합니다. 현재 런타임의 승인 고지 문구는 정확히 “이 포스팅은 네이버 쇼핑 커넥트 활동의 일환으로, 판매 발생 시 수수료를 제공받습니다.”입니다. 렌더러가 상단의 별도 고지와 승인된 실제 상품 링크를 붙이며 모델이 링크·고지를 본문에 창작하지 않습니다. 현재 해당하지 않는 글에 수수료가 생긴다고 쓰지 않습니다. 기존의 “광고 없음” 등 경제적 이해관계와 충돌하는 문구를 그대로 둔 채 제휴 링크를 숨겨 넣지 않습니다.

직접 결제했다는 사실만으로 제휴 글에 네이버 **내돈내산** 배너를 붙이지 않습니다. 실제 계정·상품·관계에 적용되는 현재 자격과 표시 기준을 별도로 확인해야 하며, 확인 전에는 사용하지 않습니다. 일반 후기의 기존 `review-editorial-v1` 사진 운반·권한·개인정보 가림 기준은 유지합니다.

새 계정 가입, 인증·구매내역 연동, OAuth/API 키 등 새 자격 증명 또는 지속 접근 권한, 유료 서비스·구매를 이 계획의 일부로 실행하지 않습니다. 필요한 별도 승인이 있을 때 해당 단계에서 진행합니다.

## 트렌드와 전환 확인

Creator Advisor에는 확인된 **유래 전용 피드가 없습니다**. 실제 질문이 음식·장소 등 화면에 존재하는 주제와 관련될 때만 그 실제 UI 분류를 참고하고 관찰된 이름을 그대로 기록합니다. 가상의 “유래” 피드·분류를 만들거나 트렌드에서 새 질문을 만들지 않습니다. 관련성이 없으면 미확인 상태를 남기고 원래 입력·수동 우선순위를 유지합니다. 유입 순위·증감은 조회수가 아닙니다.

카테고리 번호 9와 실비김치 초안의 10월 5일 저장은 확인했습니다. 화·일 확대를 위한 외부 저장·점검 지시문은 관리 오류로 동기화·재확인 대기 중입니다. 코드/문서 반영, 외부 Work 지시문 등록·읽기 확인, 대표 설정·서식 세부 검증은 각각 별도 증거가 필요합니다. 어느 한 단계의 성공을 나머지 단계의 완료로 보고하지 않습니다.
