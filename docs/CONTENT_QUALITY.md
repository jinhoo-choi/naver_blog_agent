# 주제별 콘텐츠 품질 운영 기준

버전: `topic-quality-v1` (2026-10-03). 최신 ESL 편집의 장점인 직접 답변,
자연스러운 습니다체, 짧은 의미 단위 문단과 구분선을 공통 기준으로 삼되
모든 주제를 ESL과 같은 목차로 만들지는 않습니다.

운영 배분은 2026-10-05부터 [DAILY_PLAN](DAILY_PLAN.md)의 `daily-deep-511-v1`을 따릅니다.
모든 요일에 심화 품질·실제 증거·실천 단계·체크리스트/재사용 자료·공식 직접 링크를 적용합니다.
가족-AI는 새 영상·실제 제작 자료가 있을 때만 `parenting`/네이버 1의 선택적
`editorial_type="ai_tutorial"`입니다. 화·토 AI 의무 편성은 없으며 과거 자료로 슬롯을 채우지 않습니다.
주제별 문체 기준 버전과 운영 배분 버전은 별개이며 기존 점수·모델·글당 이미지 수를 바꾸지 않습니다.

## 실제 적용 경로

실제 사용·제품·행사 후기는 명시적 `content_style="review"`에만
[후기 전용 기준](REVIEW_EDITORIAL.md)을 추가합니다. 일반 의료·운동·투자 정보 글에
개인 경험·구매 인증·후기형 사진 배치를 강제하지 않습니다.

- `src/blogbot/editorial.py`: 공통 기준과 육아·운동·투자·AI 튜토리얼의
  서로 다른 충실도 기준을 한 곳에 둡니다. 고정 소제목 템플릿이 아닙니다.
- `BlogLLM.create_draft` / `rewrite`: 기존 writer 프롬프트에 해당 주제 기준만
  추가합니다. `BlogLLM.review`: 같은 기준과 보수적 편집 관찰을 기존 reviewer에 전달합니다.
- 편집 관찰은 동일 긴 문단, 문장 내부 단일 개행, 일부 상투적 표현을 찾습니다.
  인용이나 단계별 안전 안내일 수 있으므로 자동 삭제·점수 변경·새 차단은 하지 않습니다.
  기존 6항목 점수·24점 기준·출처 확인·안전 차단·호출 횟수를 그대로 사용합니다.
- `generate_images` → `section_contexts` → `image_prompt`: 제목만 넘기던
  방식에서 실제 해당 구역의 설명을 최대 1,200자로 제한해 전달합니다.
  투자 AI 제목이면 무조건 칩과 우산을 그리던 규칙은 제거합니다.
  기존 선화/색상, 글자 제한, 안전 제한, 장수·모델·예산·재시도 수는 유지합니다.
  실제 자세의 정확성, 설명력, 본문과의 일치는 생성 후 Work가 확인합니다.
- 기존 파이프라인 카테고리는 그대로입니다. AI 튜토리얼은 육아 입력의 명시적 하위유형이며
  `ContentRequest.data.editorial_type`에 보존합니다. 새 일일 카테고리·추가 할당량·예약을
  만들지 않습니다. 외부 Work 지시문은 코드 변경만으로 자동 갱신되지 않습니다.

## 작성과 심사의 실무 질문

| 유형 | 본문에서 확인할 것 | 그림/화면의 역할 |
| --- | --- | --- |
| 육아 | 어떤 상황에서 적용하는지, 월령·조건, 적용 순서, 관찰/중단 신호 | 설명한 자세·환경·물건의 실제 차이 |
| 운동 | 준비·수행, 맞는 자세와 오류의 구체적 접점/방향/몸통 차이, 안전장치 | 원문으로 확인 가능한 자세 단서. 불확실하면 공식 동작 자료 사용 |
| 투자 | 사건 진행 단계, 원문과 기업의 연결, 남은 조건/일정, 실제 발간일 | 확인된 사건/사업 관계. 숫자는 본문·표로 보존 |
| AI 튜토리얼 | 실제 환경·설정·입력·결과·실패·재현 순서 | 실제 캡처와 실행 결과. 가짜 화면·장식 삽화는 증거가 아님 |

초반 답 → 근거 → 적용이라는 독자의 이해 흐름은 지키되 같은 FAQ·주의·결론을
매번 반복하지 않습니다. 같은 결론은 합치고, 별개의 안전 행동은 유지합니다.
단어 중간 줄바꿈을 만들지 않으며 의미별 빈 줄과 대제목 구조를 유지합니다.
네이버에서는 실제 기본 실선 구분선과 문단 간격을 확인합니다.

개인 경험이 없다는 이유로 경험을 만들거나 글을 무조건 탈락시키지 않습니다.
자료를 직접 대조한 조건 차이·해석을 저자의 분석으로 분명히 구별하면 됩니다.
사용자가 제공한 경험은 그 범위만 보존합니다. 미제공 효과 크기·사용기간·수익률·
시간 절감은 창작하지 않습니다. 실제 관찰 결과와 적용 한계는 같은 근거 구역에서
한 번 설명하며, 한계만 나열해 결과를 대신하지 않습니다.

## Work 저장·독립 작성 지시문에 적용할 최소 수정안

이 절은 외부 지시문의 유지·점검 기준입니다. 10월 5일 저장·오류점검 예약의 하루 1편
지시문 동기화는 확인했습니다. 실제 예약의 최신 지시문·대상과 모델에 전달되는 프롬프트를
함께 대조하고 불일치는 `CONFIG_SYNC_PENDING`으로 보류합니다. 변경은 승인된 범위에서만
수행하며 구성 반영을 실제 무인 저장 성공으로 보고하지 않습니다. 확인 결과는 [STATE](STATE.md)를 따릅니다.

1. 최신 main의 `docs/CONTENT_QUALITY.md`, `prompts/writer.md`,
   `prompts/reviewer.md`, `docs/BLOG_SETUP.md`, `docs/DAILY_PLAN.md`를 읽고 해당 주제의 기준을 적용합니다.
   저장 전용 예약은 새 유료 생성/심사 호출 없이 승인 원고와 실물 자료를 점검합니다.
2. 기존 지시의 '항상/정확히 5장' 부분만 아래로 교체합니다:
   '기존 글당 생성 수인 육아·운동 5장, 투자 기본 3장·본문 2,500자 이상 4장을 유지합니다.
   모든 요일에 심화 증거 기준을 적용합니다. 실제 이미지 2장 이상·공식 직접 링크카드
   1개 이상·재사용 자료 1개를 확인하고 실제 캡처 3~5장을 목표로 합니다. 중복 보조 삽화는
   생략할 수 있으며 설명과 무관한 그림으로 수를 채우지 않습니다. 추가 유료 영상·이미지는 만들지 않습니다.'
3. 기존 '개인적 효과/경험을 일절 쓰지 않음' 부분만 아래로 교체합니다:
   '사용자가 공개 반영을 확인한 경험은 원본 범위 안에서 짧게 보존합니다.
   미제공 사용·반응·정량 효과는 만들지 않으며 임상/투자 근거로 확대하지 않습니다.
   경험이 없으면 확인된 출처 비교·분석으로 설명합니다.'
4. 실제 구분선, 의미별 줄바꿈, 짧은 문단, 원문 인용을 제외한 습니다체 일관성,
   반복 결론/면책, 그림의 설명력을 확인합니다. 필수 안전 조건은 남깁니다.
   AI 튜토리얼은 실제 설정·화면·실패/결과와 미검증 제안본의 구별을 확인합니다.
5. 2026-10-05 KST부터 매일 합산 1편, 월·화·목·토·일 육아/수 운동/금 투자를 확인합니다.
   가족-AI는 새 영상·실제 제작 자료가 있을 때만 육아 안의 선택적 하위유형으로 다루며
   화·토에 강제하지 않습니다. 실제 맞는 입력이 없으면 보류하며 옛 영상/다른 글로 채우지 않습니다. 10월 5~18일은 측정 구간이고 이후에도 사용자 결정 전까지 1편을 유지합니다.
6. 09:00 준비·09:15 저장·10:15 복구 시각, 기존 모델·예산·재시도·심사/출처 문턱과
   사용자 최종 발행을 유지합니다. 당일 모든 저장·복구를 합산하고 각 receipt의 실제
   저장일/저장 시도일을 확인합니다. 기존 기록의 명시적 `day`·KST `saved_display`·시간대가
   있는 `saved_at`/`draft_saved_at`는 같은 KST 날짜여야 하며 원고 기준일/verified_date로 추정하지 않습니다.
   과거 날짜의 유료 원고는 보존·보류하며 자동 재생성·재저장하지 않습니다.
   같은 날의 복구는 원래 ID·유효 계획·기존 한도를 재사용합니다. 기존 발행글은 수정하지 않습니다.

## 기존 실행/캐시와의 호환성

이미지 프롬프트가 바뀌면 해시가 바뀝니다. 구버전 이미지 폴더를 새 작업으로
취급하면 이미 완료한 이미지를 다시 만들거나 불확실한 유료 호출의 대기/재시도
예산을 우회할 수 있습니다. 이를 막기 위해 새 이미지 작업은 `.image-plan`에
계획 키를 보관하고, 기존 무계획 폴더 또는 다른 키의 계획을 발견하면 API 호출
전 `ImagePending`으로 보류합니다. 파일·기존 예산을 지우지 않습니다.
새 작업은 정상 진행하며 같은 계획은 기존 캐시/6시간 대기/복구 예산을 재사용합니다.
보류 시 운영자는 원래 버전의 계획과 기록을 대조해야 하며, 새 request_id나
파일 삭제로 우회하지 않습니다. 이 PR은 기존 실행을 재개하거나 생성하지 않습니다.

수정 원고 복구가 `cache_only=True`이면 새 기준의 캐시 조회 실패 후 이 변경 이전의
정확한 프롬프트로 한 번 더 읽기 전용 조회합니다. 두 조회 모두 새 유료 호출을
허용하지 않습니다. 더 오래된 프롬프트 또는 다른 입력의 캐시는 계속 보류됩니다.

## 검증 범위와 남은 확인

`tests/fixtures/topic_quality.json`은 네 유형의 가상 원본/나쁜 문장/개선 발췌/
예상 심사 판단을 담습니다. 발행 가능한 원고나 사실 검증된 의학·투자 조언이 아닙니다.
`tests/test_topic_quality.py`는 선택된 기준이 작성·수정·심사에 실제 전달되는지,
네 주제가 하나의 틀로 합쳐지지 않는지, 기존 점수를 올리지 않는지, 문단/이미지
문맥, 캐시 보존과 무호출 보류를 확인합니다.

테스트 통과는 모델이 실제로 자연스럽게 쓰거나 사실·자세를 정확히 생성한다는
증거가 아닙니다. 유료 모델 생성이나 실제 블로그 발행은 실행하지 않습니다.
다음 승인된 신규 작성 때 실제 원고·출처·이미지·저장 서식을 대조해야 합니다.
외부 Work 지시문 갱신과 최신 main 사용 여부까지 확인하기 전에는 전체 운영 경로에
적용이 끝났다고 말하지 않습니다.

## 전체 오류 점검에서 보완한 저장/복구 경계

HTML 클립보드의 일반 텍스트 대체값도 문단·개행·표 셀 경계와 엔티티를 보존합니다.
일반 텍스트에는 실제 실선/볼드/이미지가 표현되지 않으므로 이 수정만으로 네이버의
서식 적용을 보장하지 않습니다. 현재 저장 확인은 목록의 제목/날짜 표시를 확인하며
저장 본문의 서식·카테고리·실제 separator를 다시 읽어 검증하지 않습니다.
실제 저장 충실도는 다음 승인된 Work 저장 과정에서 확인해야 합니다. 새 재열기
의무나 추가 저장 게이트를 이 변경에서 만들지 않습니다.

DB에 승인 원고가 남았지만 인계 JSON이 없거나 손상/다른 요청이면 해당 건만
`pending_packet_requires_reconciliation` 오류로 보류하고 다른 대기 원고를 계속합니다.
DB의 pending 상태와 파일은 유지하며 대신 작성/심사/이미지를 다시 구매하지 않습니다.
운영자는 승인 원본과 인계 기록을 복원·대조해야 합니다. DB와 파일을 하나의 원자적
트랜잭션으로 바꾼 것은 아니며, 이 경계의 실패를 안전하게 격리하는 최소 수정입니다.
손상 JSON은 암호화 인계에서도 원래 바이트를 보존하고 경로 재작성은 건너뜁니다.
DB의 pending 요청에 연결된 이미지 계획/유료 호출 기록은 손상 JSON과 무관하게
보관합니다. 복원 후에도 승인/재생성하지 않으며 동일한 조정 필요 상태로 남습니다.
