# Explicit single-use parenting repair

This narrowly scoped `manual-repair-v1` path is a separately approved repair of an
existing rejected natural manuscript. It does not relax automatic correction,
source-only review, or origins-only additional-draft guards. It never turns an
old REWRITE into PASS, resets a dated slot, or purchases another writer response.

## Authority and identity

The operator verifies the owner's actual approval of code integration, one extra
review, up to five existing-model illustrations and the additional estimated
USD1.50 budget. A reference string or external page is not authority. Use the
existing private Fernet key, current actual KST day, exact original request ID,
original request/plan, revision claim, corrected writer response, rejected review
and five-call usage history hashes. Preserve all original bytes and database
rows. No new credentials or model, permission or schedule changes are required.

The operator's corrected manuscript is explicitly labelled an editorial proposal,
not a new API-written or approved response. Its exact six draft fields and digest
are bound to one authenticated packet. One to three verified official AAP/CDC
source excerpts include URL, original text, SHA256, actual retrieval time,
verifier and `evidence_kind=selected_original_passages`. They are not described
as complete pages or as pages opened by the model. All manuscript source URLs
must have evidence; the independent reviewer still decides claim support.

## Existing workflow, bounded submissions

`Blog API Prepare` mode `manual-repair` uses the existing manual request ID,
plaintext digest and encrypted packet inputs. Its reserve phase restores prior
state, checks remote reservation history, persists a separate `repair` artifact,
and only then permits paid work in that same first-attempt owner/main workflow.
The shared workflow concurrency group remains unchanged.

- One GPT-5 reviewer submission, maximum 6,000 output tokens, no SDK or truncation retry
- Existing 24/30 minimum, accuracy and safety >=4/5, actual claim/source checks
- A failed or uncertain review stops before images
- Only after PASS, reuse the existing Flare/medium/1024x1024/JPEG image engine
- Actual image count follows the existing distinct-section plan, at most five
- Each image is n=1, one attempt, no 429 or uncertain recovery extension
- At most six paid submissions, with per-submission durable claims before API calls

USD1.50 is an **additional estimate-based allowance, not a billing ceiling**.
The preflight reserves a conservative review scenario (400k input-token assumption,
6k output, four observed search-fee units) and per-image scenarios (20k input-token
assumption, official medium1024 estimated 439 output tokens). Hosted-search input
processing and image output have no proven hard maximum. Actual known usage and
remaining estimated allowance are rechecked; missing usage is not zero. Original
spend remains separate and is included in the combined report.

## Results and transport

All new claims, input evidence, review cache, usage, images and result live under
`manual-repairs/<original-id>/`. The original global usage, cache, pre-review claim,
attempt row and rejection remain unchanged. Encrypted pack/restore transports the
new namespace and refuses stale restores that would remove or rewind claims.

A successful result is `MANUAL_REPAIR_DRAFT_READY`, outside automatic `ready.posts`
and publication candidates. Work must inspect actual images, spelling, infant
safety, manuscript/source match and rendered layout before the separately
requested draft-only save. Keep the actual save date, original ID and explicit
repair approval in the private ledger. Do not falsely insert an automatic PASS
or use an origins `additional_records` receipt for parenting.

STARTED/HELD/uncertain outcomes cannot be resubmitted under another run, date,
packet or ID. Exact completed result replay costs nothing. No publish or schedule
permission is provided by this path. Private packets, manuscript, image pixels,
keys and private ledger contents never belong in Git or public logs.
