# 모바일 블로그 작성·디자인 필수 기준

버전 `mobile-blog-v4` · 2026-11-02 최종 승인 증권사 비교 글 기준. 디자인 원칙은 모든 블로그에 적용하되 개별 글의 사실·목차·장수·회사 수를 복제하지 않는다.

## 작성 전
- 최신 요청·승인 템플릿·원고ID·저장/공개 상태를 대조한다. 이미 발행한 글의 양식 저장은 재발행·공개 수정 권한이 아니다.
- 독자의 질문과 첫 답을 정하고 필요한 표·설명 그림·실제 증거 캡처·출처 카드를 구분해 배치한다. 한 문단은 한 요점, 대체로1~3문장이다. 설명을 줄이느라 대상·기간·단위·조건·중요 예외를 지우지 않는다.
- 실제 운영 요청의 Human Writing·Avoid AI Writing 적용 기준과 승인 캐릭터 원본을 확인한다. 해당 요구가 있으면 실제 지침/원본을 열어야 적용했다고 기록한다.

## 정보 위계와 게슈탈트
- 공통 브랜드는 아이보리·오렌지·블랙을 사용한다. 과거 세이지/녹색·세피아 기본값보다 최신 승인안을 우선한다. 다른 프로젝트의 배색에는 확장하지 않는다.
- 회사/주제의 큰 제목은 네이티브 인용구2의 세로선과24px 굵은 제목으로 구획한다. 긴 혜택명은 짧은 회사명 아래 설명으로 분리한다. 승인 예시의 작은 회색 보조문은 편집기 고정13px이며16px 보존으로 보고하지 않는다. 중요한 조건은16px 본문에도 남긴다.
- 항목명16px 볼드, 설명16px 일반으로 역할을 구분한다. 전체 볼드·전체 밑줄·전 항목 색강조를 금지한다. 붙여넣기 후 굵기 상속을 실제 확인한다.
- 근접성: 항목명과 해당 설명, 캡처와 캡션·URL 카드를 가까이 둔다. 소제목 아래보다 위의 간격을 더 크게 둬 뒤 본문에 속하게 한다.
- 유사성·연속성: 동일 수준의 서식·왼쪽 정렬·항목 순서를 통일한다. 회사 블록은 기간→대상→혜택→신청/사용조건→해당 캡처→해당 URL 카드 순을 기본으로 내용에 맞게 조정한다.
- 공통영역·전경/배경: 인용구+여백 또는 실제 구분선 중 필요한 경계만 선택한다. 박스·구분선·인용구·빈 문단을 중첩해 공백을 키우지 않는다. 핵심과 배경의 대비를 확보한다. 선을 없애는 것이 목표가 아니라 주제 경계가 명확해야 한다.
- 표는 네이티브2~3열, 본문16px를 기본으로 한다. 비교 예시는2열25:75, 오렌지 머리행·아이보리 교차행이다. 실제 내용에 맞게 열너비와 정렬을 바꿀 수 있다. 작은 글씨로 맞추지 말고 셀 문장을 압축하고 조건은 인접 본문에 보존한다.

## URL 삽입: 일반 하이퍼링크로 대체 금지
1. 공식 원문의 정확한 주소·회사·기간·실제 내용을 읽어 확인한다. `source_urls`와 비공개 근거에는 원본 주소를 보존한다.
2. 네이버 상단 ‘링크 추가’→URL 입력→미리보기 확인→확인으로 실제 URL 카드를 넣는다. 본문 글자에 링크를 거는 도구 ‘링크 입력 열기’와 구분한다. HTML의 `<a>`, 주소 문자열, 가짜 카드 모양은 등록 증거가 아니다.
3. 회사 설명과 캡처 다음, 다음 회사 제목 전에 둔다. 한 문장·단락·숫자를 카드로 쪼개지 않는다. 같은 주소를 글감·URL 카드·주소로 중복 나열하지 않는다.
4. 저장본에서 카드의 제목·요약·이미지·도메인·목적지를 본문과 대조한다. 과거 연도/다른 이벤트가 미리보기에 뜨면 그대로 통과시키지 않는다. 현재 이벤트가 확인되는 공식 상세/필터 목록 등 정확한 공식 진입점으로 조정하고 원본·변경 사유를 기록한다. 메타데이터를 지어내지 않는다. 해결 못 한 필수 카드는 미완료로 남긴다.
5. 일반 글자 링크 잔존도 확인한다. 읽기 전용 DOM 검수 시 `.se-oglink`는 실제 카드, `.se-text .se-link[data-href]`는 본문 글자 링크다. `<a href>`만 검사해 링크가 없다고 결론내리지 않는다. 카드는 주소 수가 아니라 대상·위치·내용 일치로 판정한다.

## 썸네일·실제 캡처
- 다수 회사 비교의 대표는 전체 주제·기간·비교 효용을 보여주는 별도 중립 썸네일로 만든다. 첫 회사의 공식 배너를 전체 대표로 두지 않는다. 특정 회사가 대표인 글로 오인되지 않는지 축소해 확인한다. 특정 구성의 유입 효과를 보장하지 않는다.
- 실제 화면이 독자의 이해·행동·조건 확인을 돕는 곳에는 공식 페이지의 실제 화면을 확보한다. 홈페이지 첫 화면만 보여주거나 URL 카드 미리보기로 필요한 증거 캡처를 대신하지 않는다.
- 긴 전체 페이지를 작게 축소하지 말고 기간·혜택·신청·조건 등 해당 핵심 영역을 선명하게 나눠 촬영한다. 의미를 바꾸는 조건은 함께 남기고 불필요한 여백만 줄인다. 생성한 가짜 UI·재구성 이미지를 실제 화면 캡처로 쓰지 않는다.
- 비공개 기록에 공식 URL·관찰 시점·원본 크기/해시·캡처 영역을 남긴다. 공개 캡션은 필요한 대상·출처·시점·볼 지점만 적는다. 개인정보·인증정보를 배제한다.
- ‘사진 추가’로 실제 등록하고 현재 문서 목록·로딩·순서·대표 선택을 확인한다. 캡처 확보, 등록, 저장 후 판독 확인은 별개 상태다.

## 해시태그
- 일반 글의 기존 관련 태그5~8개 기준은 유지한다. 다수 증권사 이벤트 비교는 사용자 명시 예외를 적용해 본문에 포함된 모든 증권사명과 회사명+이벤트/계좌개설, 신규계좌개설·계좌개설이벤트·이벤트혜택 등 실제 키워드를 조합한다. 계정의 실제 입력 상한(이번30개) 안에서 중복·무관어를 제거한다. 본문 밖 회사를 ‘모든 증권사’라는 이유로 추가하지 않는다.
- 실제 주제 검색·상위 본문/공개 태그 근거를 확인하고 검색하지 않았다면 완료로 꾸미지 않는다. 네이티브 태그에 등록한 목록을 본문에 중복 나열하지 않는다. 날짜·회사·키워드 조합은 다음 글에서 새로 검증한다.

## 저장 후 필수 검수와 완료 판정
같은 원고ID로 저장→같은 저장본 평가→구체 결함 보완→재저장→reload 후 같은 초안 선택→PC·에디터360px 재평가→남은 수정 가능한 결함 보완→최종 저장·재열람을 직렬 수행한다. 이미 유효하게 평가된 동일 최종본은 변경·새 결함이 없으면 반복하지 않는다.

| 필수 확인 | 완료 근거 |
|---|---|
| 제목/위계 | 첫 화면의 주제, 인용구 제목·항목명·일반 본문이 구분됨. 고아 글자·전체 볼드 없음 |
| 단락/경계 | 관련 정보의 묶음, 회사 전환, 캡처·카드 소속이 명확함. 과한 공백·중복 선 없음 |
| 표/이미지 | PC·360px에서 글자·금액·기한·조건 판독, 잘림/누락/로딩 실패 없음 |
| 대표 | 별도 썸네일 실제 사진등록·대표 선택·저장본 표시 |
| URL | 필요한 대상별 실제 카드 존재, 정확한 기간/도메인/내용·인접 위치, 일반 글자링크 대체 잔존 없음 |
| 태그 | 네이티브 입력값·개수·회사 누락·표기·중복·주제 일치 |
| 사실/재사용 | 원문 조건 보존, 오래된 값/캡처/URL/날짜·자리표시자 잔존 없음 |

필수 항목의 미확인/불일치를 저장 성공이나 총점으로 상쇄하지 않는다. 새 점수표·유료 재작성·생성 루프를 만들지 않는다. 실제 확인 범위·수정 전후·남은 항목만 기록하고, 사용자 직접 발행 원칙을 유지한다. HTML 준비·내 템플릿 등록·불러오기 검증·개별 글의 등록/저장·실제 공개는 각각 구분한다.
