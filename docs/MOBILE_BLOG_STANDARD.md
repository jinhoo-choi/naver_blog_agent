# 써누애비 게시글 생성·품질 기준
버전: seonoo-production-v7 · 2026-11-18 KST

## 적용 범위와 기준
- 신규 제작·요청된 원고 수정·임시저장·검수에 이 문서를 공통 기준으로 적용한다. 현재 사용자 명시 요청을 가장 먼저 따른다.
- 이 문서는 이전 mobile-blog-v5, search-value-v1의 제작·문체·디자인·저장본 완료 판정을 통합·교체한다. 과거 문서의 상충 규칙을 병합하지 않는다. 날짜별 편성과 영수증은 최신 ledger.md에서 확인한다.
- 문체 작업에는 seonoo-human-writing, 디자인에는 apply-gestalt-design을 사용한다. Human Writing·Avoid AI Writing은 접근한 실제 참고 기준을 같은 퇴고에 적용하며 실행 여부를 구분한다. 탐지 점수를 품질 판정에 쓰지 않는다.
- 썸네일의 세부 규격은 seonoo-thumbnail-prompt.md(Library libfile_fde3_f-6441d7b9acbc819185e54a2b58f56a2d_e15e1bb13ca08191ab1bd7173369831a)의 현행 버전을 사용한다. 캐릭터 기준은 같은 지침이 지정한 한 실물로 대조한다.
- 지침 열람·파일 제작·플랫폼 등록·저장·검수·예약·공개는 별개 상태다. 확인하지 않은 상태를 완료로 쓰지 않는다. 공개·유료 실행·권한은 기존 승인 범위를 유지한다.

## 공통 집필 기준
1. 작성 전 비공개 기록에 독자 질문, 첫 답, 첫 답 이후의 추가 가치를 각각 한 문장으로 적는다. 추가 가치가 단순 재정리뿐이면 구체 사례·비교·계산·원본 장면·선택 조건을 확보해 기획을 보완한다.
2. 한 글은 하나의 중심 질문을 다룬다. 서로 다른 밈·증상·제도는 같은 결정을 설명하는 데 꼭 필요한 관계가 확인될 때만 함께 쓴다.
3. 제목 후보 2개를 비교해 핵심 검색어와 본문이 실제 답하는 효용이 분명한 것을 고른다. 기본 형식은 '핵심 검색어｜구체 효용'이다. 질문형은 실제 독자의 질문이며 첫 구간에 직접 답할 때 사용한다. 미확인 질병·효과·혜택이나 과장을 암시하지 않는다.
4. 첫 화면에 제목의 직접 답과 범위를 둔다. 밈은 관심을 끄는 장면 → 실제 원본 컷 → 뜻·웃기는 지점·쓰임 순으로 답한다. 배경·출처 나열로 답을 지연하지 않는다.
5. 직접 관련된 실제 경험이 있으면 그 장면을 쓴다. 없으면 독자의 상황과 답으로 시작한다. 아빠·선우·아내·월령·가족 대화를 도입과 결말에 강제로 넣지 않는다. '찾아봤다'도 실제 작성자 행동의 근거가 있을 때만 쓴다. 집필 도구의 조사 행위를 작성자 경험으로 바꾸지 않는다.
6. 다음 문단마다 새로운 사례·이유·조건·비교·예외 중 무엇을 추가하는지 확인한다. 같은 답 반복, 주제 밖 정보, 근거 없는 감상·교훈은 덜어낸다. 의미·적용 조건·중요 예외를 줄바꿈을 위해 삭제하지 않는다.
7. 끝에는 해당 주제에 맞는 확인된 관찰이나 적용 기준을 둔다. 인사·도움이 됐길 바란다는 말·억지 가족 이야기로 닫지 않는다.
8. 공식·원문을 직접 열어 날짜·수치·단위·조건을 확인한다. 검색 요약은 원문 탐색에만 쓴다. 최초·최대·효과·의학적 기준은 근거 범위를 넘겨 단정하지 않는다. 핵심 사실 미확보·충돌은 미확인으로 남기고 완료를 보류한다. 일반 웹 검색을 사용하고 Firecrawl은 호출하지 않는다.

## 문체 심사
- 사용자 제공 원문과 같은 매체의 확인 가능한 승인 예문을 우선한다. 예문 위치·확인한 구절·문장 호흡과 어휘를 기록한다. 말투가 확인되지 않으면 '승인 예문 대조'는 미확인이다. 추정한 예문을 승인본으로 부르지 않는다.
- 구체성: 주제명만 바꾸면 다른 글에도 그대로 통하는 문장을 해당 주제의 대상·행동·조건으로 고친다.
- 말투: 보고서식 명사 나열, 불필요한 피동·추상어, 억지 친근함을 고친다. '~합니다'를 '~해요'로 바꾼 것만으로 통과시키지 않는다. 승인 예문의 존댓말 온도와 호흡을 대조한다.
- 흐름: 문장 사이 원인·차이·행동이 이해되는지 소리 내어 읽는 방식으로 검토한다. 한 문단은 한 요점으로 쓰고 의미가 이어지는 문장은 붙인다.
- 금지 예: '오늘은 알아보겠습니다', '함께 살펴볼까요', '도움이 되셨길 바랍니다', 정보 없이 반복되는 '~하는 것이 중요합니다'. 가능성·허용·예외를 전달하는 정확한 표현은 보존한다.
- 수정 기록은 원문 → 수정문 / 이유 / 사실 보존 확인으로 남긴다. 문제가 없으면 실제 구절과 승인 예문과의 공통점을 적는다. 본문·캡션에는 검수 메모를 넣지 않는다.
- 사용자 직접 제공 문체 근거: '아기띠하고다니는 엄마들이 겨울에 패딩을 거꾸로 입고다니는줄 알았음'은 구체 관찰을 여는 방식의 참고다. 원문을 다른 주제의 경험으로 재사용하지 않는다.
- 사용자 승인 표현 근거: '대사보다 말투가 밈이 된 사례입니다.'처럼 실제 대상을 직접 설명한다. 금융·유래 등 다른 유형의 승인 예문은 현재 확인한 본문에서 확보하고 부족분을 명시한다.

## 유형별 추가 가치
| 유형 | 본문에 확보할 가치 | 적용 조건 |
|---|---|---|
| 육아·생활 | 구체적 관찰 상황 → 보호자가 할 행동 → 예외·진료 조건 | 실제 선우 사례는 제공·확인된 기록만 쓴다 |
| 후기·쇼핑 | 실제 사용 장면, 편한 점, 제약 또는 현실 팁, 적합한 사용자 | 사용 경험 없으면 정보형으로 쓰고 후기처럼 표현하지 않는다 |
| 밈 | 확인한 원본, 웃기는 지점, 실제 용례·변형의 관계 | 최초 원본 미확보 시 확인한 이른 자료라고 표시한다 |
| 금융·제도 | 같은 조건 비교, 검산 예시, 선택을 바꾸는 조건 | 최대 지급액·최대 효율·추첨·조건부 쿠폰을 구분한다 |
| 역명·유래 | 현재 장소와 이름의 연결, 확인된 연혁·어원, 지도 | 전승과 확인된 사실을 구분하고 노선도·위치도를 넣는다 |
- 아기 행동·증상 글에는 정상 발달 범위와 진료 권장 기준을 분리한다. 주제·월령에 맞는 중요한 위험 신호 3가지와 시급성을 공신력 있는 원문에서 확인한다. '무조건 정상', '진료 불필요'로 단정하지 않는다.
- 금융 비교는 핵심 비교표를 상세 설명 앞에 두고, 기간 → 대상 → 혜택 → 신청·사용조건 → 해당 공식 캡처 순으로 설명한다. 최대효율은 정의·입력값·단위·산식을 검산한 경우에만 쓴다.
- 쇼핑커넥트에는 REVIEW_EDITORIAL.md의 승인 고지·배너 기준을 추가 적용한다. 실제 상품 카드·제휴 링크·기간·제품 사양을 확인한다. 존재하지 않는 템플릿 파일에 의존하지 않는다.
- 방송 캡처는 필요한 장면 2~3장 범위, 최대 3장이다. 장면·회차를 실제 재생으로 확인하고 각 컷 아래 방송사·프로그램·회차와 공식 원본 링크를 둔다. 수량을 채우려고 불필요한 컷을 넣지 않는다.

## 모바일·본문 디자인
- 근접성·유사성·연속성·전경/배경을 정보 관계와 읽는 순서에 적용한다. 공통 브랜드는 아이보리·오렌지·블랙이다. 장식과 모든 원칙의 기계적 적용을 줄인다.
- 한 문단 한 요점을 지키고 2~3줄은 권장으로 적용한다. 360px에서 길고 빽빽하면 의미 단위로 나눈다. 조사·단위·문맥을 끊어 줄 수만 맞추지 않는다.
- 승인 비교형은 인용구2 큰 제목 24px 굵게, 항목명16px 굵게, 설명16px 일반, 보조문13px를 사용한다. 다른 유형에는 정보 위계를 맞춰 적용한다. 중요 조건은 일반 본문에서도 읽히게 한다. 전체 볼드·밑줄·중복 선을 피한다.
- 큰 소제목은 앞 묶음과 떨어뜨리고 뒤 본문과 가깝게 둔다. 이미지·캡션은 붙인다. 인용구·여백으로 구분되면 박스·구분선을 겹치지 않는다.
- 표는 비교·선택·순서를 더 쉽게 만들 때 사용한다. 네이티브 2~3열·16px·오렌지 머리행을 기본으로 한다. 반복 요약표를 모든 글에 강제하지 않는다. 긴 셀은 압축하고 조건은 인접 본문에 보존한다.
- 본문 이미지는 대표와 별도로 2장 이상을 기본으로 하고 기존 유형별 예외를 유지한다. 각 이미지가 어떤 설명을 돕는지 먼저 정한다. 목적이 겹치면 다른 자료로 교체한다. 큰 그림이 첫 답·핵심 비교표를 뒤로 밀지 않게 한다.
- 실제 사진·원본 캡처·설명 삽화를 구분한다. 생성 이미지를 체험·실제 UI의 증거처럼 쓰지 않는다. 공식 화면은 필요한 핵심 영역을 읽히게 자르고 조건·출처·시점을 보존한다. 개인정보를 제외한다.
- 하단 대표 이미지가 참고자료와 관련 글을 갈라놓는 등 흐름을 방해하면 위치를 바꾼다. 대표 등록 제약으로 위치 조정이 불가하면 실제 제약과 잔여 영향을 명시하고 완료 여부를 판단한다.

## 참고자료·목적 링크·태그
- 일반 근거 링크·URL 카드·주소는 공개 본문에 넣지 않고 하단 참고자료에 기관·자료명·확인 가능한 발행일을 텍스트 한 줄씩 쓴다. 원문 URL·관찰시각은 비공개 근거에 남긴다. 방송 컷 아래 공식 원본 링크와 필수 출처 표시는 예외다.
- 신청·구매·쇼핑커넥트 등 승인 목적 링크는 실제 목적지를 검증한다. 관련 글은 최하단 별도 구획에 현재 글의 다음 질문에 답하는 공개 글 1~2개를 네이버 링크 추가 기능으로 넣는다. 부족하면 검증한 글만 쓰고 사유를 기록한다. 무관한 링크나 미확정 슬롯을 공개 준비본에 남기지 않는다.
- 일반 태그는 실제 주제에 맞는5~8개를 기본으로 한다. 증권사 비교형의 승인 예외는 본문 회사명+이벤트·계좌개설과 실제 관련어를 관측 입력 상한 안에서 쓴다. 중복·무관어·본문 태그 재나열을 피한다.

### 심사 근거와 최종 저장본 연결

- 1차·PC 2차에는 다섯 페르소나의 실제 정수 점수를 모두 기록한다. 중간 점수가 비어 있으면 최종 평균을 확정할 수 없다. 60점 미만은 `rewrite`, 60~79점은 `revise`, 80점 이상은 `pass`다. 필수 화면 미확인 시 해당 상태는 `unverified`다.
- 같은 원고 버전에서 점수를 올릴 때는 해당 단계의 `score_corrections[페르소나]`에 위치·새 관찰·근거 파일을 남긴다. 이전 평가 이후 이번 평가 시각까지 확보한 별도 파일에 `draft_id`, `revision`, `captured_at`을 기록한다. 다른 원고 버전이면 해당 평가의 `changes`에 실제 수정 위치와 수정 근거를 남긴다. 기록 형식은 기존 evidence 항목을 따른다.
- 최종 등록 전 승인한 대표 파일을 `approved_cover`에 아티팩트 ID로 기록하고, 저장본 대표의 원본 해시를 대조한다. 네이버가 재인코딩하면 동일성을 먼저 실물로 확인하고, 편집기에 어떤 원본을 등록했는지 추적 가능한 기록을 보존한다. 확인 불가는 미확인으로 보고한다.
- 최종본을 다시 열어 PC 편집기 대표 지정 화면(`pc_representative`), 140px 목록 미리보기(`list_140`), 360px 모바일 첫 화면(`mobile_360`)을 각 이미지로 확인한다. 표가 있으면 모바일 표의 열·숫자·단위가 보이는 화면(`mobile_table`)도 확인한다. 이미지 아티팩트에 `role, draft_id, revision, captured_at`을 남기고 대표 두 화면은 `hard_checks.representative.evidence`, 모바일 화면은 `hard_checks.mobile.evidence`에서 참조한다. 각 관찰에 어떤 요소를 읽고 대조했는지 쓴다. 최종 수정·저장 이후부터 마지막 재열람 확인 시각(`reopened_at`) 사이의 근거를 사용한다. 커버·상품 이미지·다른 버전 화면을 전용 화면 자료로 재사용할 수 없다. 화면 실물과 원고의 대응은 실행자가 확인한다.

## 제작·저장 7단계
1. 후보 선정: 날짜가 맞는 전일 편성, 독자 질문·추가 가치·원문·중복을 확인한다.
2. 초안: 제목 후보·첫 답·새 정보의 흐름·말투 근거·표와 이미지 역할을 정하고 작성한다.
3. 미디어: 썸네일·본문 자료를 제작·확보하고 초안에 배치한다. 캐릭터·원본·축소 크기를 대조한다.
4. 1차 심사·보완: 아래 5개 페르소나로 원고 전체와 디자인을 심사하고 결함을 고친 구간을 다시 확인한다.
5. 임시저장: 같은 원고ID에 대표·본문·표·링크·태그를 실제 등록하고 저장한다.
6. 2차 심사·보완: 같은 PC 저장본을 다시 열어 반영·문체·흐름·대표·로딩·표·카드를 확인하고 수정·저장한다.
7. 모바일 심사·보완: 360px 또는 실제 모바일에서 첫 화면·문단·그룹·표·그림·캡션을 확인하고 보완한 최종본을 재저장·재열람한다. 실제 휴대기기를 안 봤으면 '에디터360px'라고 쓴다.
- 각 단계의 실제 시각·ID·버전·관찰·변경·재확인을 남긴다. 변경이 다른 항목에 영향을 주면 해당 범위와 후속 저장 확인을 다시 한다. 유효한 동일 최종본 근거는 재사용한다.
- 저장 결과가 불명확하면 재클릭 전에 같은 초안과 목록에서 반영 여부를 확인한다. 새 근거 없이 같은 오류를 반복하지 않는다.

## 최종 품질 심사 — 5개 페르소나
기존 제목·내용·미디어·문체·구성·정확성 6축 pass/revise 채점과 29/30·35점·다른 가중 총점은 이 5인 심사로 교체한다. 정확성은 점수와 별도의 필수 차단 조건으로 보존한다.

| 키·페르소나 | 각 20점인 세부 기준 5개 (합계 100점) |
|---|---|
| structure · 검색 체류형 모바일 편집장 | 첫 화면의 직접 답 / 문단 한 요점과 모바일 호흡 / 답·도구·근거의 순서 / 표·체크리스트의 실용성과 반복 제거 / 관련 글·참고자료·이미지 묶음의 흐름 |
| voice · 1인칭 아빠 에디터 | 확인된 경험 또는 구체적인 독자 상황 / 승인 말투·자연스러운 문장 연결 / 기계적 설명·중복·가정형 교훈 제거 / 유형별 정직함(증상 단정 금지·후기의 실제 제약) / 주제에 맞는 구체적인 마무리 |
| design · 써누애비 브랜드 디렉터 | 승인 캐릭터·브랜드·배지 / 핵심 문구·장면과 140px 판독 / 최근 3개와 구도·위계 비교 / 본문 자료와 캡션의 내용 일치·출처 / 최종 대표·표·이미지의 PC·모바일 표시 |
| topic · 네이버 SEO·미색인 방어 PD | 제목 앞 실제 검색어 / 제목의 약속과 본문의 답 일치 / 한 중심 질문·기존 글 중복 점검 / 첫 답 이후 고유 사례·계산·원본·선택 조건 / 원문 확인과 검색 의도에 맞는 범위 |
| reader · 30대 육아맘 실사용자 | 자기 상황·적용 대상을 바로 파악 / 추가 검색 없이 쓸 완성된 도구·예시 / 육아 동선·안전·현실 제약 / 금융·밈 맥락·난이도 설명 / 읽고 바로 결정·행동 가능한 결말 |

- 각 세부 점수는 0~20 정수다. 20은 확인된 기준 충족, 15는 경미한 개선 여지, 10은 중요한 보완, 5는 약속의 대부분 미충족, 0은 부재·오류를 뜻한다. 중간 점수는 실제 근거로 설명한다. 단순 요소 존재만으로 20점을 주지 않는다.
- 각 페르소나 총점은 세부 점수 5개의 합이다. 80~100점=통과, 60~79점=보완 필요, 0~59점=재작성이다. 자료·화면 미확인은 점수 null·미확인으로 두고, 확인 범위만의 진단 점수는 잠정이라고 표시한다.
- 종합은 다섯 총점의 산술평균이다. 반올림 전 평균 85점 이상(합계 425점 이상), 각 페르소나 80점 이상, 미해결 결함 0개, 필수 검수 전부 충족이어야 품질 완료다. 84.9를 85로 반올림해 통과시키지 않는다.
- 평균 85 미만 또는 개별 80 미만이면 해당 항목을 보완하고 바뀐 최종본으로 다시 심사한다. 글을 고치지 않고 점수만 올리는 행위·기본점수 일괄 부여·과거 점수 재사용은 금지한다. 적용 불필요한 하위 조건은 사유를 적고 같은 역할의 기준을 대조하며 빈 항목에 만점을 채우지 않는다.
- 출력은 페르소나별 ①점수·판정 ②실제 문장·구간의 핵심 감점 1~2개 ③즉시 수정안으로 제한하고, 80점 미만은 수정 문장·배치를 직접 제시한다. 감점이 없으면 확인한 구절·장면과 통과 근거를 쓴다. 마지막은 [종합 평균 점수]와 [발행 전 반드시 고칠 3가지]다. 미해결이 3개 미만이면 없는 결함을 만들지 않는다.

### 점수와 별개인 필수 차단 조건
hard_checks에는 facts(공식 원문·날짜·수치·조건), experience(허위 경험 없음), media_match(모든 자료와 캡션 일치), representative(최종 파일과 실제 저장본 대표), mobile(같은 최종본 모바일·재저장/재열람), disclosure(해당 광고·제휴 고지)를 둔다.
- pass/fail/unverified/not_applicable로 기록한다. pass는 실제 근거, 미확인은 사유를 남긴다. not_applicable은 광고가 없는 disclosure만 허용한다.
- 핵심 사실 오류·허위 경험·캡션 불일치·대표 불일치·모바일 미검수·필수 고지 누락은 고득점으로 상쇄하지 않는다. 점수의 통과와 저장·예약·발행 권한은 별개다.
- 필수 7단계와 같은 최종본 연결이 충족되어야 한다. 1차·PC 2차·모바일 심사에 모두 같은 5인 기준을 쓰고 당시 점수·수정 전후·revision을 기록한다. 바뀌지 않은 항목은 유효한 동일 버전 근거를 재사용한다.

### 기록 검증 계약
scripts/seonoo-review-check.py(Library libfile_fde3_f-6781ba94a8d48191aa6901efc07df988_e15e1bb13ca08191ab1bd7173369831a)는 기록·근거 파일·합계·차단 조건을 검사한다. record_valid는 문장·그림의 실제 품질을 기계가 판정했다는 뜻이 아니다.
- standard_version=seonoo-production-v7. request_id, draft_id, scored_revision, snapshot_artifact, artifacts, steps, quality, hard_checks, unresolved를 기록한다. quality의 정확한 키는 structure, voice, design, topic, reader다.
- 각 quality 항목은 status(pass/revise/unverified), score(정수 또는 null), subscores(정수 5개 또는 null), deductions(문제 위치·인용·관찰의 배열), immediate_fix(문자열), evidence를 둔다. 80 미만은 deductions와 실제 수정안이 필수다. unverified에는 reason을 쓰고 전체 평균은 null로 둔다.
- 각 review 단계(first_review, second_review, mobile_review)에 scores를 같은 5키로 기록한다. 마지막 scores는 quality 점수와 일치한다. 단계 revision·input_revision·draft_id와 실제 시각·최종 reopened_at을 보존한다.
- hard_checks의 항목은 status와 evidence 또는 reason을 둔다. unresolved는 남은 결함의 위치·관찰을 기록한다. 80 미만·fail은 남은 결함에 연결한다.
- snapshot_artifact는 실제 최종 저장본의 제목·본문·대표/본문 이미지 SHA-256·표·카드·태그를 담은 JSON 파일이다. 이 파일 바이트 SHA-256이 scored_revision이다. representative/images 원소는 {sha256}, tables는 {rows: 문자열셀 2차원 배열}, cards는 {title,url}, tags는 문자열 배열이다.
- artifacts의 근거ID마다 path(근거 루트의 상대경로), sha256, kind(text/image)를 둔다. evidence는 artifact, observation, 텍스트라면 파일에 실제 존재하는 quote를 쓴다. pass 항목은 현재 스냅샷을 인용한다. structure·design은 텍스트와 실제 이미지 근거를 함께 둔다. voice는 현재 원고와 다른 출처의 reference_evidence를 둔다.
- steps의 evidence와 비어 있지 않은 changes는 location·observation·artifact·quote를 연결한다. 이미지 파일은 실제 디코딩하고 확인 안 된 화면·장면을 근거로 만들지 않는다.
- 실행: python3 seonoo-review-check.py RECORD.json --request-id ID --revision SHA256 --artifact-root EVIDENCE_DIRECTORY. status=record_valid, quality_decision=pass, total>=85를 확인하고 실행자가 실제 심사 근거를 검토한 뒤 품질 완료를 보고한다. API 호환·안전 계약은 별도 보존하며 네이버 5인 심사를 대신하지 않는다.
