# 후기형 편집·저장 기준

현재 편성은 [DAILY_PLAN](DAILY_PLAN.md), 실행·공개 권한은 [AUTOMATION](AUTOMATION.md)이 우선합니다. 아래 날짜별 승인 기록은 당시 이력이며 일반 정보 글의 이미지 수량 강제로 확대하지 않습니다.

버전: `review-editorial-v1` (2026-10-05). 사용자가 제공한 사진과 경험을 읽기 쉬운
후기로 배치하는 추가 기준입니다. [CONTENT_QUALITY](CONTENT_QUALITY.md)의 공통 품질·
안전·출처 기준과 [INPUTS](INPUTS.md)의 실제 자료·권한 확인을 함께 적용합니다.

## 적용 범위와 변경하지 않는 것

- 명시적으로 검증된 `ContentRequest.data.content_style="review"`인
  `parenting`·`exercise`·`cooking`에만 적용합니다. 제목·제품명·사진 유무로 추정하지 않습니다.
  `origins`·`investment`와 `editorial_type="ai_tutorial"`에는 적용하지 않습니다. 유래의 향후 구매·제휴 연결은 [ORIGINS_EDITORIAL](ORIGINS_EDITORIAL.md)을 따릅니다.
- `content_style`은 같은 주제 안의 편집 스타일 메타데이터입니다. 새 카테고리·주제 선택·
  일일 슬롯·할당량이 아니며, 생략한 일반 글의 작성·심사·저장 기준은 그대로입니다.
  요리는 기존처럼 별도 요청일 때만 다룹니다.
- [DAILY_PLAN](DAILY_PLAN.md)의 날짜별 계획과 하루 합산 1편을 유지합니다. 10월 5일은 `daily-deep-511-v1`, 10월 6일부터는 `weekly-4111-v1`의 월수토일 육아/화 유래/목 운동/금 투자입니다.
  이 후기 기준은 소유자 지정·수동 슬롯과 알테오젠 수동 지정, `CUTOVER_ACTIVE` 전환 조건을 바꾸지 않습니다.
- 기존 모델·글당 유료 이미지 계획·예산·심사 점수·출처 문턱·캐시·재시도·복구 한도를
  유지합니다. 이 기준을 맞추기 위한 새 유료 작성·심사·이미지·영상 호출은 하지 않습니다.
  자료가 부족하면 원래 승인물과 이력을 보존하고 해당 문제를 보류합니다.
- 공개된 기존 글에는 소급 적용하지 않습니다. 최종 발행은 사용자만 합니다.

## 1. 네이버 기본 내돈내산 기능

네이버 안내에서 내돈내산은 작성자가 직접 구매·이용했고 리뷰 대가로 경제적 이익을
받지 않았음을 스스로 보증하는 기능입니다. 네이버가 사용 경험이나 제품 품질을
독립적으로 검증했다는 뜻이 아닙니다. 실제 인증내역 컴포넌트가 첨부된 글에
상단 배너가 표시됩니다. [네이버 기능 소개](https://help.naver.com/service/5593/contents/22399?lang=ko&osType=COMMONOS)

후기마다 필수로 넣지 않습니다. 아래 조건을 모두 확인한 경우에만 기본 기능을 사용합니다.

1. 사용자가 해당 후기의 대상에 대해 직접 결제·이용했고 협찬·환급 등 리뷰 대가를
   받지 않았음을 확인했습니다. 사진이나 주문 화면만으로 이 사실을 추정하지 않습니다.
2. 현재 편집기의 내돈내산 선택 화면에서 해당 실제 구매·이용 내역이 적격 항목으로
   선택 가능합니다. 실제 항목과 후기 대상이 맞는지 확인합니다.
3. 삽입 후 카드에 비공개 가격·주문 정보·이름·연락처·주소 등 공개하지 않을 정보가
   보이지 않습니다. 사용자가 가격 제외를 요청했다면 카드에도 적용하며, 기본 기능으로
   숨길 수 없다면 카드를 생략합니다. 카드나 배너를 조작해 인증처럼 보이게 만들지 않습니다.

PC는 스마트에디터 ONE 상단, 앱은 하단 더보기의 내돈내산 기능에서 실제 항목을
선택합니다. 현재 화면을 확인하고 없는 버튼·연동 상태를 추정하지 않습니다.
[네이버 첨부 방법](https://help.naver.com/service/5593/contents/22400?lang=ko&osType=COMMONOS)

기간 경과, 다른 글에 이미 첨부, 취소·환불, 미지원 서비스 등으로 목록에 항목이
없을 수 있습니다. 적격 항목이 없거나 확인할 수 없으면 선택적으로 생략하고 상태를
기록합니다. 인증 부재만으로 경험을 창작하거나 같은 글을 다시 생성하지 않습니다.
[네이버 첨부 불가 사유](https://help.naver.com/service/5593/contents/22401?lang=ko&osType=COMMONOS)

이 작업은 구매 내역·본인인증의 새 연동, 새 개인정보 동의, 자격증명 생성이나
지속 접근 권한 확대를 포함하지 않습니다. 그런 단계가 필요하면 진행하지 않고
사용자 직접 조치가 필요하다고 알립니다. 내돈내산 배너를 텍스트·이미지로 모방하거나
실제 컴포넌트 없이 인증 완료·검증된 구매라고 주장하지 않습니다.

## 2. 사진 입력과 화면의 순서·배치

후기 입력은 실제 제공 사진을 사용합니다. `photos[]`의 `file`과 선택적 `caption`을
기준으로 하며, 선택적 `origin`은 `owner` 또는 `seller`, 선택적 `role`은 `hero`로
표시할 수 있습니다. `origin="seller"`이면 확인 가능한 공개 `source_url`이 필요합니다.
`section_heading`을 지정하면 원고의 정확히 일치하는 구역 제목에만 연결하며,
대응하는 제목이 없으면 임의 구역으로 옮기지 않고 보류합니다.

관리 입력 큐의 사진 합계는 전송 여유를 위해 12 MB 이하로 제한합니다. 사진 장수 기준이
아니며, 새 후기 등록과 복원 큐 확인에서 유료 작성 전에 검사합니다. 초과하면 원본·기존
이력을 지우지 않고 등록/처리를 보류합니다. 별도로 승인된 작은 입력 준비가 필요하며
자동 압축·삭제·새 ID로 한도를 우회하지 않습니다. 공급 사진은 암호화 인계에 포함하고
복원 시 큐·원고·DB의 경로를 함께 바꿉니다. 최종 암호문이 55 MB를 넘으면 기존 인계 파일을
덮어쓰지 않습니다. 이는 60 MB 읽기 한도의 방어선이며 무제한 이력 보관을 보장하지 않습니다.

후기 사진이 없으면 유료 이미지 호출 전에 보류하며, 생성 이미지로 실사진을 대신하지
않습니다. 모델에는 사진의 캡션·메타데이터를 전달할 뿐 이미지 픽셀을 직접 보여 주는
것이 아닙니다. 모델이 사진 실물을 봤다고 주장하지 않으며, 실제 사진과 설명의 일치·
배치·개인정보 가림은 저장 작업이 시각적으로 확인합니다. 일반 글의 기존 생성 이미지
수량·예산은 바꾸지 않습니다.

- 사용자가 제공하고 블로그 반영을 승인한 실제 사진을 먼저 사용합니다. 대표 사진과
  착용·사용 모습의 핵심 사진은 본문 폭의 단독 큰 사진으로 배치해 전체와 디테일을
  볼 수 있게 합니다. 첫 사진 위치와 네이버 대표 이미지 지정은 별도로 확인합니다.
- 포장·구성품·관련 소품처럼 함께 비교할 이유가 있는 사진만 2열로 묶습니다.
  모바일에서 대상·글씨·차이가 충분히 보일 때만 사용하고, 작아지면 단독 배치합니다.
  모든 사진을 콜라주로 만들거나 기계적으로 두 장씩 짝짓지 않습니다.
- 판매자 상세페이지처럼 긴 화면은 실제 사용 사진 뒤, 해당 설명과 가까운 위치에
  둡니다. 설명에 필요한 최소 부분만 사용하고 확인된 출처 URL을 남깁니다.
  저작권·재사용 권한을 확인하며 전체 페이지나 타인 사진을 통째로 복제하지 않습니다.
  필요한 맥락을 지워 잘못된 인상을 주는 자르기도 하지 않습니다.
- 사진 총수를 전역으로 고정하거나 특정 장수를 채우려고 중복·무관한 사진을 더하지
  않습니다. 기존 주제별 생성 계획·품질 문턱과 실제 제공 자료 범위는 유지합니다.
  기존 유료 계획의 수량과 최종 본문에 필요한 사진 수를 혼동하지 않습니다.
  이 기준은 부족한 실물 자료를 유료 이미지로 대체하라는 지시가 아닙니다.

## 3. 문단·정렬·서식

후기형 본문은 한 문단에 한 가지 요점, 대체로 1~3문장으로 구성합니다. 의미가 바뀔 때
빈 줄을 넣고 문장이나 단어 중간을 고정 글자 수로 끊지 않습니다. 기존 자연스러운
습니다체와 핵심 답을 전하는 짧은 2~3문장 도입을 유지합니다. 실제 발언·인용은 보존합니다.

정보·설명·조건·목록은 왼쪽 정렬합니다. 짧은 소감은 필요한 경우에만 가운데 정렬할 수
있으며, 긴 설명까지 가운데 정렬하지 않습니다. 강조색은 한 가지로 절제하고 같은
문장을 여러 방식으로 과장해 강조하지 않습니다.

본문 16px·대제목 24px·소제목 19px, 요약만 20px 볼드인 기존 기준을 유지합니다.
도입 뒤 대제목 구역과 참고자료 앞에는 편집기의 실제 기본 실선과 문단 간격을 확인합니다.
문자 `---`나 자동 줄 감김으로 대신하지 않습니다. 반복된 결론·면책은 줄이되 별개의
안전 조건과 중단·응급 행동은 남깁니다. 이 기준은 모든 글에 동일한 목차를 강제하지 않습니다.

## 4. 사진에 붙이는 실제 경험과 제외 요청

제공된 경험은 해당 내용을 보여 주는 사진의 바로 앞이나 뒤에 짧게 연결합니다.
사진만으로 알 수 없는 조립·설치 시간, 사용 기간, 효과, 반응, 가격, 장점·단점을
만들지 않습니다. 사진의 외관 관찰과 사용자의 실제 경험도 구분합니다.

사용자가 말한 단점은 범위 안에서 보존하되, 균형 잡힌 후기처럼 보이게 하려고
가짜 단점을 추가하지 않습니다. 미제공 결과·아이의 반응·사용 편의성을 추정해
개인 경험으로 쓰지 않고 임상적 효과나 투자 근거로 확대하지 않습니다.

사용자가 가격을 빼 달라고 한 경우 본문·제목·캡션·판매자 화면·내돈내산 카드 모두에서
그 요청을 유지합니다. 다른 공개 자료에서 가격을 찾았다는 이유로 다시 넣지 않습니다.
제외한 정보를 숨길 수 없는 자료는 생략하거나 사용자 확인이 필요한 사항으로 남깁니다.

## 5. 저장 직전 점검과 태그

사진 업로드 전에 원본 실물과 전체 배송 라벨·개인정보 가림을 먼저 확인합니다.
편집기는 자동 저장될 수 있으므로 미가림 사진을 먼저 올리지 않습니다. 이후 최종
임시저장 버튼을 누르기 전에 이미 열려 있는 편집기에서 아래 항목을 확인합니다.

1. 모든 이미지가 실제 로드됐고 승인 자료와 일치하는지, 사진 순서·대표 설정·단독/2열
   배치가 맞는지, 모바일에서 읽을 수 있는지 확인합니다. 미확인 화면은 확인했다고 쓰지 않습니다.
2. 캡션과 인접 경험이 사진과 맞고 미제공 사실을 추가하지 않았는지 확인합니다.
   공개 미승인 가족·아동 정보와 비공개 가격 등도 확인합니다.
3. 배송 라벨은 이름·주소 한 줄만이 아니라 송장번호·연락처·바코드·QR 등 전체 라벨이
   식별 불가능하게 가려졌는지 확인합니다. 다른 사진·캡처에도 같은 정보가 남지 않아야 합니다.
   가림이 확인되지 않으면 그 자료를 올리거나 저장하지 않습니다.
4. 링크카드와 선택적 내돈내산 카드의 대상·제목·미리보기·출처·개인정보를 확인합니다.
   가짜 배너·인증 표현과 가격 제외 위반이 없어야 합니다.
5. 문단·정렬·실제 구분선·기존 글꼴/크기·강조색이 맞는지 확인하고, 동일한 내용이나
   segments·태그가 중복 삽입되지 않았는지 확인합니다. 큰 사실·구조 수정은 기존처럼 보류합니다.
6. 후기 인계 segments는 본문 태그를 붙이지 않습니다. post.tags를 확인하고
   네이버 기본 태그 입력이 지원되면 그 한 곳에 입력합니다. 지원되지 않아 본문 태그를
   쓰는 경우에도 한 곳만 사용합니다. 같은 태그를 본문과 기본 입력에 두 번 넣거나
   15개 고정 목록을 덧붙이지 않습니다. 기본은 관련 태그 3~5개·최대 8개이며,
   사용자가 해당 글에 명시한 태그·개수 지시가 있으면 그 범위로 적용하고 중복은 제거합니다.

저장 직전 점검을 저장 후 자동 재열기 검증으로 바꾸지 않습니다. 기존 절차대로
완료 표시와 목록의 동일 제목·실제 저장시각을 확인한 경우에만 `SAVED_NAVER`로 기록합니다.
불확실하면 `SAVE_UNCERTAIN`으로 보존하고 목록 조정 전 다시 저장하지 않습니다.
저장 이력·개인정보·원래 ID·예산·복구 규칙은 변경하지 않습니다.

## 실제 적용 경로와 확인 경계

- `src/blogbot/editorial.py`와 `llm.py`는 검증된 후기 스타일의 작성·수정·심사 경로에
  해당 기준을 전달합니다. 일반 글에 후기 기준을 강제로 붙이지 않습니다.
- `inputs.py`는 `content_style`을 검증·보존하고 제공 사진을 관리 경로에 보관하며
  파일 해시를 확인합니다. 판매자 출처·사진 메타데이터도 실제 제공 범위로 다룹니다.
- `images.py`는 후기의 제공 사진을 증거 자료로 사용하고 유료 생성 이미지로
  대체하지 않습니다. 기존 체크포인트·이력·예산을 보존합니다.
- `presentation.py`는 대표 사진과 명시적 구역 제목의 연결 및 출처/배치 순서를
  처리합니다. Python이 네이버 내돈내산 기본 컴포넌트나 2열 UI를 직접 구현·검증했다는
  뜻이 아닙니다. 해당 편집기 기능과 모바일 가독성은 Work의 실제 화면에서 확인합니다.
- 주 운영 경로인 Cloud API는 제공 사진을 사용한 후기와 인계 패킷을 준비하고,
  Work가 실물·개인정보·사진 배치 점검을 마친 뒤 임시저장을 진행합니다.
- 직접 Playwright `NaverDraftWriter` 경로는 후기형을 보류합니다. 시각·개인정보·
  배치 점검 없이 배송 라벨이 남을 수 있는 제공 사진을 네이버로 바로 업로드하지
  않습니다. 이 보류를 우회하거나 검증되지 않은 직접 업로드를 성공으로 처리하지 않습니다.

문서·자동 테스트는 실제 화면의 사진 내용, 라벨 가림, 네이티브 카드나 모바일 배치를
검증했다는 증거가 아닙니다. 새 유료 호출 없이 다음 승인된 Work 저장에서 별도로 확인합니다.

## 외부 저장 지침에 반영하는 범위

저장 지침의 기존 편집·저장 절에 후기형 조건부 보충만 둡니다. 최초 또는 검증한 SHA가
바뀌었고 실제 스타일이 `review`일 때만 필요한 이 문서 절을 추가 대조합니다.
일반 글이나 오류점검마다 문서·작성/심사 프롬프트 전문을 다시 읽지 않습니다.

오류점검 지침은 최신 저장 운영지침을 참조하고 저장 연결만 합니다. 후기 검수는 실제
저장 작업이 맡으며, 오류점검에 네이버 직접 편집·추가 재열기·중복 호출을 추가하지 않습니다.
다음날 Creator Advisor 수집은 기존 KST 당일 1회 시도 기록·한도·비공개 전달 경로를
그대로 유지합니다. 문서·코드 변경만으로 실제 예약이 갱신되거나 무인 저장이 검증된 것은
아니며, 외부 지침의 적용 및 실제 실행 결과를 각각 확인해야 합니다.
