대화 맥락 기준: 2026-09-27 KST · 구현 버전 0.4.0

## 사용자 확정 사항

- 블로그명·프로필명 `써누애비`, 소개글·프로필 이미지·상단 스킨 적용 완료.
- 네이버 카테고리: 육아 1, 요리 6, 투자 7. 최종 발행은 사용자 직접 처리.
- 요리는 제공한 레시피와 실제 사진이 모두 있을 때만 작성.
- 육아는 선우 관련 실제 질문을 입력으로 작성. 월령·증상·경험을 추정하지 않음.
- 투자는 `jinhoo-choi/kis-community-bot`의 기준 통과 자료만 읽기 전용으로 사용.
- 작성 전 네이버 검색 상단 5~10개 글의 구조를 비교하되 조회수 순위라고 표현하지 않음.
- 육아·투자 이미지는 밝은 생성 이미지 사용. 요리는 사용자 원본 사진만 사용.

## 현재 구현

- 대제목 4개 이상·소제목·짧은 문단, 육아 1,800자 최소 기준.
- 검색 노출 글의 글자·이미지·소제목·표·FAQ·체크리스트 메타데이터만 보관.
- 1차 자료 기반 사실 검수와 네이버 구조 비교를 분리.
- 육아 2장·투자 1장 생성 후 대제목 사이에 첨부. 실패 시 저장 중지.
- 네이버 카테고리 번호로 편집기 진입, SmartEditor HTML 서식·사진 업로드, 저장 목록 제목 확인.
- 요리 입력의 레시피·사진·해시 검증, 투자 원본 커밋·기준일 보존.
- 발행 자동화 없음. 저장 불확실 시 자동 재시도 중지.

## 실계정 반영

- 사용자 확인: 기존 임시저장 3건 전부 직접 발행 완료, 애드포스트 신청 완료. 승인 여부·수익은 아직 확인되지 않음.
- 2026-09-27 KST 실제 발행 목록과 게시글별 통계 접근 확인: 목튜브, 호명반응, 아톤 투자 메모 총 3건.
- 사용자 최종 발행 원칙 유지. 발행 글의 제목·본문은 자동 수정하지 않음.

예약 지침에는 최신 프로젝트 문서 읽기, 실제 육아 질문 조회, 투자 원본 심사,
네이버 상단 노출 5~10건 구조 비교, 밝은 이미지, 저장 확인, 주제·당일 중복 방지가 포함됩니다.
가용한 다른 입력을 검토해 3건 완성을 시도하며, 자료·품질 기준을 낮추거나 경험을 창작하지 않습니다.
이미 발행한 목튜브·호명반응·아톤 글 3건은 첫 실행의 신규 3건에 포함하지 않습니다.
예약 등록·네이버 편집기와 임시저장 접근·투자 원본 읽기를 확인했습니다.
무인 예약의 첫 실제 실행·3건 저장 완료는 아직 미래의 확인 항목입니다.

현재 예약은 사용자 PC의 Windows runner를 호출하지 않습니다.
GitHub Actions와 n8n은 별도 대안이며, 중복 실행 방지를 위해 함께 활성화하지 않습니다.
네이버 세션 만료나 CAPTCHA는 사용자 인증이 필요할 수 있으며 우회하지 않습니다.

## 발행 후 3일 통계와 작성 프롬프트 개선

2026-09-27 추가 요청에 따라 기존 새벽 예약의 글 작성 전에 아래 단계를 실행합니다.
별도 중복 예약을 만들지 않습니다. 현재 실행 대상은 ChatGPT Work 경로이며 PC 실행기에는 통계 수집 코드를 추가한 상태가 아닙니다.

1. 발행 목록과 게시글 ID·발행 시각을 읽고, 아직 분석하지 않은 글 중 72시간이 지난 글을 선택합니다.
2. 네이버 게시글 통계에서 일별 조회수·공감수·댓글수와 제공되는 유입경로·검색어를 수집합니다.
   현재 확인한 화면은 일간 집계이므로 발행일 D0부터 D2까지 3일을 사용하며, 첫날은 부분 일자로 기록합니다.
   정확한 발행 후 72시간 통계로 표현하지 않습니다. 미집계·미제공은 0으로 바꾸지 않습니다.
3. 카테고리·주제·노출 기간을 구분해 비교합니다. 블로그 전체의 평균 사용 시간 등을 개별 글 지표로 대입하거나 노출수 없이 CTR을 계산하지 않습니다.
4. 근거가 있는 개선점만 제목의 검색 의도, 도입부 답변, 소제목 순서, 설명·표·이미지 배치에 반영합니다.
   표본이 적으면 성과 결론을 보류하고, 제한된 실험은 가설로 표시합니다. 한 번에 1~2개만 바꿉니다.
5. 비공개 성과 기록의 '현재 적용할 작성 프롬프트'를 갱신하고, 같은 실행의 다음 글 작성 전에 읽어 적용합니다.
   근거 글·기간·수치·변경 전후·버전을 기록해 복구할 수 있게 합니다. 원시 통계와 기록은 공개 저장소에 올리지 않습니다.
6. 동일 게시글·기간의 분석을 중복 적용하지 않습니다. 통계 접근 실패나 데이터 부족 시 기존 프롬프트를 유지하고 초안 작성을 계속합니다.
7. 결과에는 분석 건수·보류 사유·프롬프트 변경 1~2개를 함께 보고합니다. 기존 사실성·안전성·개인정보·카테고리·이미지·최종 발행 원칙이 우선합니다.

현재 3건은 2026-09-27 00:23~00:24 KST 발행으로, 첫 분석은 2026-09-30 새벽에 조건 충족 여부를 확인합니다.
9월 27~29일 데이터 집계가 지연되면 다음 영업일로 넘깁니다. 지금은 성과 기반 개선 규칙을 확정하지 않았습니다.

## 비용 산정 범위

- 현재 ChatGPT Work 예약은 기존 ChatGPT 구독의 사용 한도·크레딧을 사용합니다.
- GitHub Actions/n8n/Windows 실행기 및 별도 OpenAI API를 활성화하지 않은 현재 경로의 별도 서버·API 추가비는 0으로 산정합니다.

- 실제 추가 크레딧 비용은 첫 실행 이후 계정의 사용량·결제 내역으로 추정해야 합니다. 애드포스트 예상 수입으로 상계하지 않습니다.

## PC 실행기 대안의 연결 상태

| 항목 | 상태 |
|---|---|
| OPENAI_API_KEY | GitHub Secret 등록 확인. 값은 조회하지 않음 |
| NAVER_BLOG_ID | GitHub Secret에 `choijku` 등록 |
| GitHub Variables | 경로·모델·후보 수·스케줄/알림 플래그 등록 |
| Windows self-hosted runner | 사용자 PC에서 1회 등록 필요 |
| 네이버 최초 로그인 | 실행기 PC에서 1회 필요 |
| GitHub 자동 스케줄 | BLOG_SCHEDULE_ENABLED=false를 2026-09-27 화면에서 확인. ChatGPT 예약과 동시 활성화 금지 |
| n8n | 선택 연결. 가져오기 JSON 준비 |

PAT는 사용하거나 저장하지 않았습니다. PC 실행기는 ChatGPT 대화를 상시 수집하지 않으며 실제 질문을 개인 입력 큐에 등록합니다. 현재 ChatGPT 예약은 실행 시 프로젝트 대화·개인 맥락에서 확인한 실제 질문을 사용합니다.
